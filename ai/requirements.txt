# Runtime dependencies, pinned exactly. A range here would let a rebuild months
# from now resolve a different driver than the one this stack was verified
# against, on an image that is otherwise reproducible.
#
# psycopg 3, not psycopg2, and the [binary] extra rather than the pure-python
# build. The extra ships a wheel with libpq compiled in, which is what keeps
# `libpq-dev` and gcc out of the image. There is an apt layer in ai/Dockerfile as
# of MEMO-13, but it installs ffmpeg and nothing else -- no compiler and no
# `-dev` package reaches this image on the driver's account.
#
# What this does *not* decide is glibc versus musl, and the first version of this
# comment claimed it did. Checked against PyPI instead of asserted: psycopg-binary
# 3.3.4 publishes musllinux_1_2 wheels for x86_64, aarch64, ppc64le and riscv64
# alongside the manylinux ones, so alpine would install it from a wheel just fine.
# ai/Dockerfile has the reason the base image is slim anyway, and it is a different
# package's problem.
psycopg[binary]==3.3.4

# The local speech-to-text path (MEMO-14). MIT, like CTranslate2 under it and the
# Whisper weights it fetches -- no account, no key, no rate limit, and offline
# after the first fetch.
#
# It is the expensive line in this file and the number is worth having in front of
# whoever reads it next: 330 MB of site-packages, taking the ai image from 822 MB
# to about 1.25 GB, measured on arm64. Four packages are most of it -- ctranslate2
# (60 MB, the inference engine), PyAV and its bundled ffmpeg libraries (95 MB),
# onnxruntime (50 MB, for the voice-activity filter) and numpy (66 MB).
#
# PyAV's copy of ffmpeg genuinely is a second one: ai/Dockerfile installs Debian's
# for the `ffmpeg` and `ffprobe` binaries memo_ai/audio.py shells out to, and this
# is the in-process decoder faster-whisper reads the normalized file with. Not
# worth removing -- the alternative is feeding whisper raw samples this project
# would then have to decode itself, to save a fraction of what the model weights
# cost once MEMO-15 bakes them in.
faster-whisper==1.2.1

# The local enrichment path (MEMO-21): llama.cpp, in this process, running the
# Qwen2.5-1.5B-Instruct GGUF that ai/Dockerfile bakes. MIT, like the binding, and
# Apache 2.0 for the weights -- no account, no key, no network.
#
# **It is the one line in this file with no wheel behind it.** PyPI carries an
# sdist and nothing else for this package -- checked, not assumed: the 0.3.34
# release publishes exactly `llama_cpp_python-0.3.34.tar.gz`. So a plain
# `pip install` compiles llama.cpp from source and needs cmake and a C++
# toolchain, which is why ai/Dockerfile builds it in a stage that is thrown away
# rather than installing a compiler into the image that ships. That takes about
# 2m15s on a cold build and nothing at all on a warm one.
#
# The upstream project does publish binary wheels, at their own index rather than
# on PyPI. Declined: it would mean an `--extra-index-url` pointing at a GitHub
# Pages site for a package this stack executes model weights through, and the CPU
# wheels there are x86_64 -- NOTES.md requires this image to be arm64-native, so
# the one machine it was built for is the one that index does not serve.
#
# Cheap once built: 19 MB of site-packages, 17 MB of which is the compiled
# `libggml`/`libllama` shared objects themselves. Beside faster-whisper's 330 MB
# and the weights' 1,117 MB it does not register.
llama-cpp-python==0.3.34
